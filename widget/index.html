messaging-ai widget — dev shell

This page simulates a customer-site host. The widget mounts itself in a Shadow DOM and shows a launcher in the bottom-right corner. The data-key on the script tag is the public widget key the server resolves to a tenant.

Walkthrough — verify all 6 states

  1. Closed. → Look bottom-right: floating accent "Chat with us" pill.
  2. Open + empty. → Click the launcher. Panel opens with header, "Ask anything" empty state, focused composer.
  3. Open + history. → In the dev controls bottom-left, click darija RTL. Confirm: customer Darija-Arabizi bubble (LTR), AI Darija-Arabizi reply (LTR), customer Arabic-script bubble (RTL — tail flips to the right), AI Arabic-script reply (RTL). Tail corner sits on the speaker's side in both directions.
  4. Open + sending. → Type any message, press Enter. The user bubble appears; three bouncing dots replace the cursor while the mock thinks (~450ms).
  5. Open + streaming. → Reply text accumulates ~8 chars at a time; breathing cursor at the end of the AI bubble until done. Try Je veux un remboursement (PAYMENT_DISPUTE), nhder m3a wa7ed agent (EXPLICIT_REQUEST), ????? (OUTSIDE_SCOPE).
  6. Open + error. → Click error in the dev controls. Top-of-panel red banner appears; composer disabled. Click clear to reset.

RTL composer check

Type واش عندكم directly into the composer. The textarea dir should flip to rtl at the first Arabic-script character. Erase back to empty; dir reverts to ltr.

Reduced motion

System Settings → Accessibility → Reduce motion. Reload. The panel slide-in, bubble fade-in, dot bounce, and cursor breath all stop animating. Other interactions still work.

Console

The widget exposes window.MessagingAI with open(), close(), toggle(), identify({ name, email }), and destroy(). Try MessagingAI.toggle() in the devtools console.
